# 🛒 Smart Tekh — интернет-магазин

![CI](https://github.com/Denis227U/Smart_Tekh/actions/workflows/ci.yml/badge.svg)

## 📌 О проекте

Современный и быстрый интернет-магазин, построенный на базе актуального стека технологий с акцентом на высокую производительность, строгую типизацию и поддерживаемую, масштабируемую Feature-Sliced Design архитектуру.

## 🧰 Стек

### Текущий
- **Frontend:** Next.js 16 (App Router + cacheComponents), TypeScript
- **Управление состоянием:** Zustand 5 + persist (с кастомной SSR-safe гидратацией)
- **База данных:** Prisma 7, PostgreSQL
- **Хранение файлов:** MinIO (объектное хранилище для статических изображений)
- **Валидация:** Zod (клиент + сервер)
- **UI:** Базовые компоненты в shared/ui (Button, Loader, Icon, Container, Modal, Heading, Field, Accordion, FieldCounter и др.)
- **Архитектура:** Feature-Sliced Design (FSD), строгий порядок импортов (eslint import/order по FSD), строгая валидация .env
- **Инструменты:** ESLint, Prettier, Husky, Commitlint, GitHub Actions, Docker
- **Аутентификация:** NextAuth v5 (Credentials, Google and Yandex OAuth), Middleware-защита роутов
- **Функционал каталога:** Полноценный каталог товаров с фильтрацией, сортировкой, пагинацией и синхронизацией всех параметров через URL

### В планах
- **Тесты:** Vitest + React Testing Library


## 💻 Локальный запуск

### 1. Клонирование репозитория
```bash
git clone https://github.com/Denis227U/Smart_Tekh.git
cd Smart_Tekh
```

### 2. Установка зависимостей
```bash
npm install
# или pnpm install / yarn install
```

### 3. Запуск базы данных (Docker Compose)
Запуск базы данных PostgreSQL и объектного хранилища MinIO:
```bash
docker compose up -d
```

### 4. Настройка переменных окружения
Создайте файл `.env` в корне проекта, скопируйте .env.example в .env и заполните необходимые значения:
```env
# База данных (Prisma 7)
DATABASE_URL="postgresql://myuser:mypassword@localhost:5434/mydb?schema=public"
```
*Примечание: myuser, mypassword и mydb — значения по умолчанию из docker-compose.yml*

### 5. Миграции базы данных (Prisma 7) и наполнение тестовыми данными
```bash
# Накат миграций из prisma/migrations и генерация Prisma Client
npx prisma migrate dev

# Сидирование базы данных
npx prisma db seed
```

### 6. Запуск сервера разработки
```bash
npm run dev
```
Проект откроется по адресу: `http://localhost:3000`

## ⚡ Технические особенности каталога
* **URL как Single Source of Truth:** Фильтры, сортировка и характеристики полностью синхронизированы с `searchParams`. Это позволяет пользователям делиться ссылками с сохраненными фильтрами.
* **Оптимизация навигации (push vs replace):** Ввод цен защищен дебаунсом и обновляет URL через `router.replace`, чтобы не засорять историю браузера. Выбор остальных фильтров и сортировки идет через `router.push`, что позволяет пользователю отменять шаги кнопкой «Назад».

## ⚡ Технические особенности страницы товара
* **Двунаправленная синхронизация (Thumbs Sync):** Основной слайдер товара жестко синхронизирован с нижним мини-слайдером (thumbnails).
* **Архитектурная готовность к анонимизации данных (onDelete: SetNull):** Схема БД заранее спроектирована с учетом удаления аккаунтов в будущем; при удалении пользователя его отзывы не будут удаляться, чтобы сохранить общую статистику товара. Поле `userId` зануляется, полностью анонимизируя текст и оценку.
* **Защита от спама через частичный уникальный SQL-индекс:** Введено ограничение: **один пользователь — один отзыв на товар**. Standard Prisma `@@unique` не подходит (т.к. NULL никогда не равен другому NULL), поэтому добавлена кастомная SQL-миграция с **частичным индексом (Partial Index)**. База жестко пресекает спам от авторизованных юзеров, но разрешает хранить неограниченное число анонимизированных отзывов.
* **Бесконечный скролл отзывов (Cursor-based Infinite Scroll):** Первая пачка отзывов рендерится на сервере. Вместо смещения `skip` (которое дублирует или пропускает данные при добавлении новых отзывов) используется пагинация по уникальному идентификатору.

## ⚡ Технические особенности корзины (Cart Flow)
* **Atomic Transactions (`prisma.$transaction`):** Синхронизация данных с БД обернута в изолированную транзакцию. Это гарантирует консистентность данных при пакетной перезаписи (`deleteMany` + `createMany`) и полностью исключает ситуации «частичного» сохранения или потери данных.
* **Anti-Tampering (Защита от подмены цен):** В `localStorage` сохраняется минимальный кортеж данных (`productId`, `quantity`). Все актуальные цены, старые цены, заголовки и медиа маппятся строго с сервера через базу данных, что исключает любые манипуляции со стоимостью на клиенте.
* **Hydration Shield & Race Conditions Protection:** Инфраструктурные хуки `useClientStore` и `useStoreHydration` на базе React 19 `useSyncExternalStore` предотвращают ошибки *Hydration Mismatch* при работе Next.js с локальным хранилищем. Использование `useRef` блокирует гонку данных (race conditions) при параллельных рендерах страницы.
* **FSD Slot Composition:** UI компонент товара корзины `CartItemRow` (`entities/cart`) не знает о глобальном стейте и внешних интерактивных фичах — кнопки изменения количества (`ChangeCartItemQuantity`) и удаления (`RemoveFromCartButton`) передаются в него через слоты из слоя `widgets`. Это гарантирует переиспользуемость верстки и соблюдение архитектурных границ.
* **Асинхронные стратегии синхронизации (Debounced vs Immediate):** Операции мутации корзины разделены по критичности сетевого взаимодействия:
    - *Добавление и изменение количества:* Реализованы через дебаунс-синхронизацию. Сетевые запросы группируются и отправляются на сервер с задержкой `SYNC_DELAY` только после того, как пользователь прекратил активные клики, что предотвращает спам БД.
	- *Удаление товара:* Выполняется без дебаунса. Запрос на удаление отправляется на сервер незамедлительно, чтобы гарантировать мгновенное освобождение остатков или корректный пересчет корзины без сетевых задержек.
    - *Optimistic UI c Rollback:* Удаление товара происходит мгновенно на клиенте. В случае сбоя сети стор автоматически производит откат стейта (`Rollback`) к исходному состоянию и триггерит UI-нотификацию для пользователя.
* **Dual-Mode Sync & Guest Merge:** Логика оркестрируется хуком `useInitialCart` и Server Action-функцией `syncCart`. В зависимости от статуса авторизации система распределяет логику на три сценария, где серверное взаимодействие `syncCart` разделено на два режима:
    1. *Guest Session (Сессия гостя):* При отсутствии `userId` система работает локально, извлекая плоские данные из `localStorage` и обогащая их актуальными ценами и остатками (`stock`) с сервера через метод `getCartProducts` без прямой записи в БД.
    2. *Merge Strategy (Авторизация гостя):* Если пользователь переходит из статуса гостя в авторизованного, накопленные в `localStorage` товары сливаются с серверной корзиной в БД (`isMerge: true`). При совпадении `productId` алгоритм выбирает наибольшее количество (`Math.max`), защищая выбор пользователя. Флаг слияния кэшируется в `sessionStorage` для предотвращения повторных проверок при дедупликации рендеров.
    3. *Overwrite Strategy (Активная сессия / Перезапуск):* В состоянии активной сессии клиент становится единственным источником правды (Single Source of Truth). Изменения пакуются и отправляются на сервер пачкой с задержкой дебаунса (`SYNC_DELAY`), полностью перезаписывая серверный стейт (`deleteMany + createMany`, `isMerge: false`) на основе актуальных локальных данных.
